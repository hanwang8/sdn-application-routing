# SDN 应用感知路由与自动化验证

基于 Ryu 和 OpenFlow 1.3，让同一对主机之间的不同应用流量走不同路径，并用一条命令完成部署、发流和路径判定。

## 拓扑与路径

```text
              +---- s2 ----+
              |   上路径   |
h1 (10.0.0.1)-s1          s4-h2 (10.0.0.2)
              |   下路径   |
              +---- s3 ----+
```

| 流量 | 路径 |
|---|---|
| HTTP（TCP/80） | h1 → s1 → s2 → s4 → h2 |
| 大文件传输（TCP/5001） | h1 → s1 → s3 → s4 → h2 |
| ARP 和其他 IPv4 | 默认走上路径 |

## 流表设计

控制器在交换机接入时主动下发规则，不依赖 Packet-In。s1 和 s4 用优先级区分流量，s2 和 s3 只在两个端口之间转发。

| 优先级 | 匹配条件 | 作用 |
|---:|---|---|
| 300 | 入端口 + IPv4 + TCP + 目的或源端口（80 / 5001） | 按应用选择路径，两个方向都要匹配 |
| 200 | 入端口 + ARP | 让地址解析走上路径 |
| 100 | 入端口 + IPv4 | 其他 IP 流量的默认转发 |

回程规则按 TCP 源端口匹配，所以请求和响应走同一条路径。

## 验证方法

`automated_demo.py` 会依次完成下面的步骤：

1. 启动 Ryu 控制器和 Mininet 拓扑。
2. 用 ping 确认基本连通，并完成 ARP 学习。
3. 记录 s2、s3 接口的字节计数，发起 HTTP 请求，再次读取计数并比较增量。
4. 用同样的方法发送 8 MiB 数据，并确认服务器收到的字节数正确。
5. 只有两类流量都走了预期路径才输出 `PASS`，否则退出码为 1。

## 测试结果

连续运行 3 次，全部通过（完整输出见 [results/demo-run.log](results/demo-run.log)）：

| 流量 | 上路径增量（字节） | 下路径增量（字节） | 结果 |
|---|---:|---:|---|
| HTTP | 1,661 | 0 | PASS |
| 8 MiB 传输 | 0 | 8,411,269 – 8,423,875 | PASS |

增量比 8 MiB（8,388,608 字节）略大，因为接口计数是收发字节之和，还包含协议头和 ACK 等开销。

测试环境：Python 3.8.5、Mininet 2.3.0、Ryu 4.34、Open vSwitch 2.13.1。

## 运行方法

需要在已安装 Mininet、Ryu 和 Open vSwitch 的 Linux 环境中运行，并具有 root 权限：

```bash
sudo mn -c
```

```bash
sudo python3 automated_demo.py
```

加上 `--pause` 可以在每个阶段暂停，方便现场演示：

```bash
sudo python3 automated_demo.py --pause
```

## 已知局限

- **路径是静态的：** 只按端口号分流，不感知链路负载，也没有处理链路故障。
- **端口和拓扑写死：** 规则只适用于这个四交换机拓扑。
- **只验证了路径：** 字节计数能证明流量走了哪条路，但这个实验没有测吞吐和时延。
